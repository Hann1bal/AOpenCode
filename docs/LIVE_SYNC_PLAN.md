# Live Session Sharing — синхронизация двух OpenCode-серверов (форк-архитектура)

Задача: телефон (AOpenCode) и домашний OpenCode — два связанных узла. **Локальный
opencode-сервер телефона сам подключается к домашнему серверу** и реплицирует его
сессии в свою базу. WebView всегда говорит только с локальным сервером — никакой
«подмены webui» на удалённый хост.

## 0. Что уже есть в OpenCode v2 (проверено по исходникам anomalyco/opencode, dev)

Сессии event-sourced: `event` / `event_sequence` (aggregate_id, seq, **owner_id**),
проекции `session_v2` / `session_message` / `session_part`, контент в `blob`.

Ключевые находки в ядре:

1. **`commitDurableEvent` (packages/core/src/bus.ts:290)** — движок применения
   внешних durable-событий в локальную базу:
   - явные `seq`, `aggregateID`, `ownerID`, `strictOwner`;
   - идемпотентный реплей (тот же event id+payload на том же seq → no-op);
   - детект расхождения (`Replay diverged at aggregate X seq N`);
   - owner-притязание и блокировка чужих агрегатов (`strictOwner`);
   - транзакционный прогон проекций перед персистом.
   Это готовый механизм репликации чужих агрегатов (строился под облако/migration).

2. **Пассивные HTTP-примитивы** (достаточно клиенту, сервер дома не меняется):
   - Pairing: `POST /api/pair` → одноразовый код (5 мин);
     `GET /auth/connect/:code` (Accept: application/json) → `{token}` на 30 дней,
     Basic-auth `opencode:<token>`; ротация серверного пароля отзывает всё.
     CLI: `opencode pair` (QR + ссылки).
   - `GET /api/info` — version/hostname/urls (проверка совместимости).
   - `GET /api/experimental/session/:id/export?sanitize=` — полный транскрипт.
   - `POST /api/experimental/session/import` — верное создание сессии (create-only!).
   - `GET /api/experimental/session/:id/log?after=<seq>&follow=true` — SSE
     durable-события после курсора + watermark `log.synced`, дальше live.

3. **Чего нет**: стокный сервер никуда не звонит сам; import не умеет
   инкрементально дополнять существующую сессию (create-only); плагин-API v2
   (packages/plugin) не даёт ни import, ни доступа к Bus — плагином не решить.

Вывод: «сервер подключается к серверу» требует **форка opencode** с тонким модулем
UpstreamSync поверх уже существующего ядра. P0 — контракт-тест эндпоинтов против
запиненного 2.2.5 (`/doc` из assets).

## 1. Архитектура

```
┌────────────── телефон ───────────────┐         ┌────────── дом ──────────┐
│ WebView ──► opencode serve (ФОРК)   │         │ opencode serve (сток)   │
│              127.0.0.1, всегда      │         │  OPENCODE_SERVER_PASSWORD│
│                   │                 │         └───────────▲─────────────┘
│      UpstreamSync (модуль форка)    │  pairing token 30d│
│  tail /session/:id/log?after=seq ───┼───────────────────┘
│  commitDurableEvent(owner=home)     │
└─────────────────────────────────────┘
```

- **Дом**: без кода. `opencode serve` + `opencode pair`.
- **Телефон**: форк opencode, запущенный с upstream-конфигом. Держит постоянные
  SSE-хвосты по домашним сессиям, реплицирует события в свою базу.
- **UI**: стокный веб-UI локального сервера. Домашние сессии — обычные сессии в
  списке, с бейджем происхождения и read-only статусом.

## 2. Модуль UpstreamSync (форк opencode, TS/Effect)

### 2.1 Конфиг
Env-переменные (инжектит Android через `BackendManager.start()`):
- `OPENCODE_UPSTREAM_URL` — база домашнего сервера;
- `OPENCODE_UPSTREAM_TOKEN` — pairing-токен (Basic-auth);
- `OPENCODE_UPSTREAM_ID` — стабильный id пира (для ownerID);
- флаг режима: `mirror` (все сессии) / `watch:<ids>` (выбранные).

### 2.2 Поток репликации
1. Старт: `GET /api/info` (проверка версии) → `GET /api/session` (курсорный
   листинг) → список домашних сессий.
2. На каждую сессию: `GET .../log?after=<local seq>&follow=true`.
   Локальный курсор — `event_sequence.seq` этого агрегата в локальной базе.
3. Каждое durable-событие → `commitDurableEvent(def, event, { seq, aggregateID,
   ownerID: "peer:<upstream-id>", strictOwner: true })`.
   Проекции сами обновляют session_v2/messages/parts.
4. `log.synced` watermark → курсор подтверждён, хвост live.
5. Реконнект: backoff → повторный log с текущего курсора. Идемпотентность
   реплея делает дубли безвредными; расхождение — явная ошибка, не тихая порча.

### 2.3 Семантика владения
- Домашние агрегаты: owner = `peer:<home>`. `strictOwner` блокирует любую
  локальную запись в них (агент на телефоне не может испортить домашнюю сессию).
- Локальные сессии: owner = local, на репликацию не влияют.
- Реплика — полноценная запись в локальной базе: поиск, просмотр, экспорт,
  офлайн-доступ.

### 2.4 «Забрать себе» (takeover)
Форк реплики в локально-владельческую сессию: новый агрегат, owner = local,
копия событий до выбранной точки (внутренне — тот же commitDurableEvent со своим
owner, либо export→import с новым id). Домашняя копия остаётся нетронутой.
После takeover это две независимые сессии — **вопрос «мерджа» не возникает**.

### 2.5 Стриминг: хвост = стрим, GUI видит единую шину
Топология «1 GUI, много серверов, локальный — мастер»:

```
WebView (GUI) ──► локальный мастер (форк) ── Bus → SSE /event ──► GUI
                     ├── upstream: дом    (tail durable-log)
                     ├── upstream: работа (tail durable-log)
                     └── локальные сессии (owner = local)
```

- `commitDurableEvent` вызывается с `publish: true` → реплицированные события
  попадают в ЛОКАЛЬНУЮ шину и в локальный `/event` SSE.
- GUI стримит домашние сессии идентично своим: печать ответа, tool-вызовы,
  todos — в реальном времени. GUI не знает происхождение событий, мастер
  унифицировал все источники в один поток.
- Из WebView в удалённые серверы не уходит ни одного запроса — только мастер
  ходит на апстримы.

### 2.6 Handoff — продолжение ТОЙ ЖЕ сессии (тот же ID)
Отличие от takeover: не новая копия, а смена владельца агрегата.

**Со стокным домом:**
1. Домашняя сессия idle → «Взять под управление» в клиенте.
2. Мастер: `Bus.claim(aggregateID, "local")` (bus.ts:699) + фиксация
   handoff-watermark = seq дома на момент захвата.
3. Телефон продолжает сессию под local-владельцем, ID не меняется.
4. Хвост к дому не закрывается: события дома после watermark → явный
   `Replay diverged` → UI «призрачная ветка» (что дом сделал после захвата,
   выбор: телефон авторитетен / пересобрать). Тихой порчи нет.

**С форком на обоих концах (полный follow-режим):**
- Смена владельца — durable-событие `session.owner.claimed {from, to, atSeq}`
  в том же event-log; реплицируется как все события.
- Оба конца tail-ят друг друга; сессия следует за пользователем
  дом → телефон → дом: один ID, одна история.
- Гонки решаются seq-механикой ядра; запись в чужой агрегат отбивается
  `strictOwner` с обеих сторон; «призрачные ветки» не нужны — владелец известен.

### 2.7 Что реплицируется, а что нет
- Реплицируется: durable-события сессий (история, сообщения, parts, todos).
- Не реплицируется: файлы репозитория (это git), креды провайдеров, конфиги.
  Для продолжения takeover/handoff-сессии агентом нужен локальный checkout —
  UI предупреждает. Опция sanitize-экспорта для «тянуть только контекст».

## 3. Сторона Android (тонкий слой)

- `sync/PairingClient.kt` — редим pairing-кода (QR со `opencode pair` или
  вставка ссылки): `GET /auth/connect/<code>` → токен; `GET /api/info` →
  проверка версии.
- `sync/PeerStore.kt` — пиры в существующем EncryptedSharedPreferences.
- `BackendManager.start()` — инжект upstream-env в ProcessBuilder; не уходить в
  idle, пока есть активные upstream-сессии в работе.
- `ui/PeersActivity.kt` — QR-скан, статус пира, отзыв токена.
- Бейджи «home / read-only» и кнопка takeover: если стокный UI не даёт —
  минимальный патч форка UI или отдельный нативный экран-триггер.
- **Не нужно**: Room-зеркало, переключатель цели WebView, свой транспорт.

## 4. Сборка (CI)

Вместо `npm pack @opencode/cli-linux-arm64-musl` в `prepare-assets.sh`:
1. Клон форка, пин версии opencode + bun (тот, которым собирается апстрим).
2. `bun install && bun build --compile --target=bun-linux-arm64-musl` (или
   штатный скрипт сборки opencode для этого таргета).
3. Бинарь в assets/runtime, чексуммы в assets.lock (как сейчас).
4. Контракт-тесты: docker-пара (сток-дом + форк-телефон) — export/import/log,
   реплей с owner, takeover.

## 5. Безопасность

- Pairing: одноразовый код 5 мин → токен 30 дней в EncryptedSharedPreferences;
  отзыв = смена пароля дома.
- Транспорт: tailnet (100.64/10) / RFC1918; публичный интернет — только HTTPS с
  pinned-отпечатком. Cleartext вне приватных диапазонов запрещён (конфиг уже есть).
- WebView остаётся на 127.0.0.1 — поверхность атаки не растёт.
- Реплики read-only на уровне ядра (strictOwner) — данные дома защищены от
  случайной записи с телефона.
- Транскрипты в локальной базе телефона: app-private storage, бэкапы исключены.

## 6. Фазы

**P0 — Верификация ядра (1–2 дня)**
- Собрать форк из исходников под linux-arm64-musl, бинарь в assets.
- Контракт-тест 2.2.5: наличие import/export/log/pair в `/doc`.
- PoC: две машины, tail log → commitDurableEvent с ownerID → сессия видна в UI.

**P1 — UpstreamSync MVP + стриминг**
- Модуль: листинг, tail, реплей (`publish: true`), курсоры, реконнект,
  owner-семантика.
- Android: pairing (QR) + инжект env.
- Acceptance: домашняя сессия **стримится** в UI телефона в реальном времени
  (печать, tool-вызовы, todos) через локальный SSE; офлайн-просмотр работает;
  локальная запись в реплику невозможна.

**P2 — Takeover + Handoff**
- Takeover: «Забрать себе» → локальная сессия-владелец; предупреждение про checkout.
- Handoff: `Bus.claim` той же сессии + watermark; «призрачная ветка» при
  расхождении со стокным домом.
- Acceptance: продолжил ту же сессию на телефоне (ID не меняется), дома
  история цела; продолжение дома после захвата детектится явно.

**P3 — Мульти-пир и hardening**
- Несколько upstream-ов, выбор сессий для watch, лимиты, нотификации,
  e2e в CI, обработка снов/смен IP дома.

**P4 — Follow-режим (форк на обоих концах)**
- `session.owner.claimed` как durable-событие; двунаправленный tail;
  сессия следует за пользователем между машинами без призрачных веток.

**P5 — Апстрим PR**
- Оформить UpstreamSync как отдельный модуль и подать в anomalyco/opencode
  (owner_id + commitDurableEvent явно рассчитаны на это). Цель — сбросить
  поддержку форка на мейнтейнеров.

## 7. Чего сознательно НЕ делаем

- Не реплицируем через Room/app-слой — источник истины телефона это его сервер.
- Не переключаем WebView на удалённый хост.
- Не делаем авто-мердж транскриптов (и так не нужно после takeover-модели).
- Не пишем в базу в обход Bus — только через commitDurableEvent.
- Не меняем домашний сервер — он остаётся стокным.
